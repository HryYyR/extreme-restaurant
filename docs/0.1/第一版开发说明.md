## 2. 第一版实现范围

### 核心循环

第 1 天开店前夜晚 → 布置 / 购买 / 换菜 → 校验 → 固定经营窗口 → 自动闭店 → 复盘 / 自动缴租 → 下一晚或胜败。

- 默认 120 秒，前 80% 时间生成到店计划；时间是模拟时间，不是系统日历。
- 暂停冻结全部模拟；白天操作只允许观察。
- 同 tick 上菜优先于等餐扣分；截止 tick 正好吃完可结账。
- 未吃完不结账；闭店取消旧任务，清空全部库存。

### 自动经营

- 厨师：优先最早无供应订单，可合批同菜；先用厨房余量，再烹饪并搬往出餐口。
- 服务员：先送手中食品 / 订单，再领取可送食品，最后找最近待点单客人。
- 客人：FIFO 排队、预留座位、选菜、待点单、等餐循环扣分、用餐、唯一结账。
- 订单、食物、桌位、灶台与配送责任只有唯一拥有者；取消后释放，食品守恒。
- 四方向格子寻路；NPC 不互相硬碰撞，减少非策略性的避让死锁。

### 夜晚与资源

- 一格菜谱、两格不同 Buff，每夜只刷新一次；取消替换不会扣钱。
- 收藏保留旧菜，夜晚免费换入；上架多菜不是强制。
- 六类 Buff 使用共享剩余营业天数池、效果加算、叠层涨价与上限。
- 金币支付商品与房租；声望购买员工 / 桌位 / 菜单容量。
- 四笔递增租金，最后一天付款成功才胜利。
- 不加入工资、材料、清洁、贷款或实时手操。

### 观察与复盘

- 角色状态、烹饪进度、等餐循环和剩余耐心。
- 收入按菜与客人类型拆分；霸王餐计完成但不计有金币付款人数。
- 声望基础获得、Buff 获得、品质扣分、等餐原始 / 实际扣分。
- 到店终态漏斗、闭店阶段、点单 / 等餐均值与 P90、桌位 / 灶台利用。
- 服务员 / 厨师的移动、工作、空闲记录；库存生产 / 消耗 / 损耗。
- 建议最多突出两个问题，是启发式提示而非最优策略承诺。

## 4. 美术替换与人物动作接入

使用 Godot SpriteFrames 资源，给每种角色设置帧动画。程序提供六种语义：idle、walk、cook、order、carry、eat。

以厨师配置为例（示例资源路径不存在，需要由美术创建）：

~~~json
{
  "chef": {
    "frames": "res://assets/actors/chef_frames.tres",
    "scale": 0.3,
    "offset": [0, -6],
    "animation_map": {
      "idle": "Idle",
      "walk": "Walk",
      "cook": "Cooking",
      "order": "Interact",
      "carry": "Carry",
      "eat": "Eat"
    }
  }
}
~~~

- frames 为空时用程序生成占位。
- scale 调整源图显示尺寸，offset 调整局部锚点；不影响地图占用与寻路。
- animation_map 把模拟语义映射到美术动画名；缺少某动作时回退 idle / 可用动画。
- 烹饪 / 点单 / 用餐都由模拟 deadline 决定。禁止从动画结束信号发钱或生成食物。
- 字体可在 manifest 的 font 字段接入项目内 FontFile。当前 PC 使用已安装中文字体回退；网页交付前必须打包具有合法分发授权的中文字体。
- 当前设施为代码绘图；可以替换 WorldView 的绘图或接入设施场景，但保持设施 ID、格子占用和交互点契约。

## 5. 临时数值调整依据

原文中的宏观预算表不是实际收入证明。实现后先做首日 / 整章模拟，发现并调整：

1. 初始桌子离出餐 / 订单口过远，服务员绝大部分时间在走路；首日未修改策略的固定种子只有 8 位完成、192 金币。
2. 收紧初始布局，服务员临时移速由 2.5 改为 3.5 格 / 秒；同种子基础首日达到 15 位完成、360 金币。
3. 15 秒等餐扣分让扩桌后的普通收入声望被反复抵消；临时周期改为 20 秒、最长改为 80 秒，边界测试仍可构造 15/60 夹具。
4. 原租金 2000/4000/6500/9500 下，参考策略 12 种子全部未过最终压力；不是证明所有策略都无法通关，但不适合把它当已验证首版曲线。
5. 临时租金调整为 1800/3200/5000/7500，宏观目标曲线同步更新，随后再次进行自然预算整章对照。

改动都已同步设计文档与配置版本。没有通过隐藏赠币、免扣声望或修改第 28 天规则来让测试通关。
