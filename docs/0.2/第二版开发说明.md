# 第二版（0.2 优化）开发说明

- 日期：2026-11-24
- 规则依据：项目根目录《游戏设计与开发基准》v0.4
- 配置 / 存档版本：0.3.0 / 2
- 引擎与平台：本机 Godot 4.6.3，PC 优先，网页未交付
- 范围：功能实现和轻量单日压力测试；**本轮不做完整平衡或通关率验收**

## 优化项落实

1. **白天**：120 秒为到店窗口，不是强制关店时间；客源计划处理完且入店客人都自然离开后自动结算，玩家无手动结束入口。第 120 秒后显示清场状态；左上房租框附简短当日 / 明日事件预告。提供 1×/8× 快进切换，暂停与切后台暂停保持不变。
2. **后期客流**：四段基础普通人数为 36 / 90 / 230 / 680。新增门庭若市 Buff（普通人数 +50%，2 天），第 22、27 晚保底可买。第 22 天购买后的计划到店为 1,040（普通 1,020 + 稀有 20）；周末的事件修正另行加算。
3. **队列**：无排队自然离场。仅未入座客人占用队列；满额的新客（包括稀有 / 事件特别客人）计拒客，不生成实体、不扣声望。初始容量 24，每次花声望 +128，最终可到 1,048。容量并不等同于餐桌、厨师和服务员的服务能力。
4. **全屏信息设计**：地图覆盖整个窗口；白天场景不显示到店、排队、等餐的实时汇总数字。顶中太阳 / 月亮天数圆标与今日收入、左上下一次房租、右上设置、夜晚底部开店。收入显示“0$”形式。
5. **物品交互**：新增收银台实体，点击打开五项声望升级；老虎机实体点击后在右侧显示简介，点击采购进入“左厨师角色 / 随机气泡、右侧商品”页面。普通设施和 NPC 左击浮出统一详情，夜晚可从详情操作家具。
6. **人物反馈**：等餐由条形改为头顶圆形进度；剩余总耐心也使用圆环。稀有与特别客人脚下显示名字。角色动作仍经 SpriteFrames 映射，不影响经济模拟时间。
7. **输入与设置**：右键按住拖镜头，左键点击对象查详情；设置齿轮打开居中菜单，含暂停 / 继续、复位视野、重开、退出。
8. **存档**：旧 0.2.2 档案不迁移；启动时提示不兼容，未经玩家确认不写入。确认建立新局时旧检查点移作备份。测试使用独立文件，不改正常进度。

## 当前检验

- 56 条规则与事务回归通过；旧 120 秒强制结算用例已改为自然清场。
- 原生窗口 28 项布局 / 点击 / 采购 / 排队扩容 / 暂停 / 快进 / 右键移动 / 自动复盘检查通过，1440×900 留有夜晚、采购、营业、清场、结算五阶段截图。
- 第 22 天购入门庭若市：到店计划 1,040 次；默认容量 24 的样例中入店 43、拒客 997，最终自然清场且物品 / 人数守恒。**这是默认未扩队的功能夹具，不是建议的最终拒客比例。**
- 将队列预置为升级上限 1,048：到店 1,040、入店 1,040、拒客 0；仅做 120 秒接客窗口容量 / 性能检查（本机该段模拟约 1.4 秒），没有宣称已检验 1,040 人自然清场耗时。
- 人工体验与经济平衡尚未验收。若购买大量队列容量而不扩员工、餐桌，清场会很久；快进与策略调整是必要的观察对象。

## 自查与轻量UI优化（2026-11-24）

确认并修复：

- 右键在浮层或窗口外松开后，镜头的拖动状态可能继续残留；现在每次鼠标移动都核对真实按键掩码。
- 夜晚点击预览厨师/服务员会显示空白或前一次详情；现在有独立的夜晚人物说明。
- 人物头部和稀有名字明明可见却点不中；热区与可见身体、脚下名字对齐。
- 快进按钮曾显示“下一步要切换的倍率”，不是当前速度；现在当前1×/8×直接可见，高倍速有不同底色。
- 非法配置可能让快进停在0倍率、队列升级步长为0或缺少必需容量字段；配置加载会拒绝这些情况并给出原因。

此外，可点设施悬停显示描边与手形指针、布置目标有效/被占分别用绿/红提示、特别事件客脚下使用红色标签、禁用购买按钮提示原因，短消息末尾渐隐。玩法计价、租金与存档格式未变。

本次新增的**61 项规则回归、9 项无窗口UI逻辑检查**通过；第22天客流测试仍为1040次到店尝试，默认队列自然清场与1048人容量窗口检查均通过。此前的28项原生窗口检查是样式调整之前的记录；本轮原生GUI复验未得到执行许可，docs/0.2的截图也尚未更新，请在编辑器F5试玩时重点检查新悬停与标签的视觉效果。未进行完整经济平衡。
